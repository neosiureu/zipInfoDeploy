# ⑤ 해마·좋아요 사전 등록 글 (v0, 순서 6b)

관문 3의 계획서(01 254~264줄, 설계안 11절)에 넣을 ⑤의 몫이다. 코드는 ai-core의 `Memory`·`MemoryNotice`와 하네스의 `MemoryFile`(memory 명령)이다. [ ] 칸은 시운전이 끝나 얼린 뒤에 채운다.

## 1. 채울 실행

- 시운전 설정(`settings/pilot_v0.json`)의 계획에 든 판 **c09(전부)** 의 실행 모두다(설계안 7.6의 v0 제안, 01 129줄).
- 설정은 연습 나눔이고 `files.memory`가 null이다. 그래서 채울 실행은 빈 기억으로 돈다(안내가 없고, 카드는 ID 순이다).
- 아래 가운데 하나라도 있으면 얼리지 않는다.
    - 끝나지 않은 실행(기록에 `end`가 없음). 이어 돌려 끝낸 실행은 끝난 실행이다.
    - 기록이 없는 실행
    - 계획 밖의 c09 기록
    - 요청 지문이 그때의 코드·설정과 다른 c09 기록
- 일부 실행만 써야 할 일이 생기면 이 글을 고쳐 따로 정한다.
- 쓴 실행: 150개(계획에 든 c09 실행 수와 같다, 순서 11b-1 7). 실행 ID 목록은 얼린 파일의 `run_ids`에 있다.

## 2. 뽑는 법(기억)

- `trade_stats`만 본다. 막힌 꼴은 셋이다.
    - 거절: 장치가 막은 부르기
    - 오류: 도구 오류
    - 0건: 받아들여졌으나 표본이 0
- 막힘은 매물의 부르기(매물의 API, 매물의 현재 코드)가 와야 닫힌다.
    - 거절·오류는 그 부르기에서 닫힌다. 그 부르기가 0건이어도 닫힌다.
    - 0건은 그 부르기에 표본이 있어야 닫힌다.
    - 다른 부르기는 받아들여져도 막힘을 닫지 않는다.
- 닫힐 때 막힌 부르기와 api나 region_code가 다르면 뽑는다. 값은 둘 가운데 바뀐 칸만 "칸=값"으로 적는다(둘 다 바뀌면 "api=…, region_code=…"). 기간·deal·dong·jibun은 바뀌어도 세지 않는다.
- 항목은 (막힌 꼴, 막힌 값, 풀린 값, api)이고 매물의 현재 시군구 아래에 둔다.
    - api가 바뀐 길이면 api 칸은 풀린 api(매물의 API)다.
    - 지역 코드 길이면 api 칸은 빈 글이다.

## 3. 합치기와 찾기

- 같은 길(막힌 값, 풀린 값, api)은 시군구마다 한 항목이다.
    - 낸 실행 수는 그 길을 낸 실행마다 한 번 센다.
    - 꼴은 그 길을 낸 실행에서 본 꼴마다 실행 수를 세어 가장 많은 것이다. 같으면 글자 순으로 앞선 것이다(0건, 거절, 오류 차례).
- 찾기: 매물의 현재 시군구로 찾는다.
    - 지역 코드 길은 같은 시군구의 모든 매물에 보인다.
    - api가 바뀐 길은 풀린 api가 매물의 API와 같은 매물에만 보인다.
- 차례: 낸 실행이 많은 순, 같으면 (막힌 꼴, 막힌 값, 풀린 값, api)의 글자 순이다. 이 차례로 K = 2개를 고른다.

## 4. 안내(모델이 보는 글)

- ⑤가 켜진 판에서만, 첫 사용자 글의 맨 앞(질문 앞)에 3절의 항목을 많아야 K = 2줄 둔다. 줄 사이는 줄바꿈 하나, 안내와 질문 사이는 빈 줄 하나다.
- 한 줄의 꼴
    - 지역 코드 길: `지난 실행에서 막혔다 풀린 길(같은 시군구, 꼴): 막힌 값 → 풀린 값`
    - api가 바뀐 길: `지난 실행에서 막혔다 풀린 길(같은 시군구·API, 꼴): 막힌 값 → 풀린 값`
    - 꼴은 거절·오류·0건, 값은 2절의 "칸=값"이다.
- 보일 항목이 없으면 안내가 없다. 첫 사용자 글은 질문부터다.

## 5. 좋아요

- 같은 채울 실행 가운데 받아들여진 제출로 끝났고, 마지막 제출의 기록 전용 대조에 걸린 것이 없는 실행만 센다.
- 그 실행에서 `read_card`로 읽은 카드마다 1을 더한다. 한 실행에 한 번이고, 오류 난 읽기는 뺀다.
- 정답과 채점 결과는 쓰지 않는다.
- ⑤가 켜진 판은 `search_cards`와 ⓪의 카드를 좋아요 많은 순(같으면 카드 ID 순)으로 낸다. 꺼진 판은 카드 ID 순이다.

## 6. 얼리기

- experiment/harness에서 `memory settings/pilot_v0.json c09 <얼릴 파일>`로 얼린다. 이미 있는 파일은 덮어쓰지 않는다.
- 파일은 JSON, UTF-8, 줄 끝 LF다.
    - 칸 차례가 정해져 있다.
    - 항목은 시군구 글자 순이고, 그 안은 3절의 차례다. 좋아요는 카드 ID 순이다.
    - 같은 기록이면 바이트까지 같다.
- 그 파일을 두 곳의 설정 `files.memory`에 건다.
    - 설계안 10.3의 "얼린 뒤 연습 문항으로 한 번 더"
    - 본실험
- 걸면 ⑤가 든 판(c08·c09)의 요청 지문 memory 칸이 그 파일의 SHA-256(줄 끝 LF로 맞춤)이 된다.
- 얼린 파일: `harness/frozen/memory_v0.json`(순서 11b-1 7에서 얼림, 순서 11b-2에서 커밋). 시군구 6가지, 항목 10개, 좋아요 카드 9장이다.
    - SHA-256(줄 끝 LF로 맞춤): 앞뒤가 `0C74B76B…BA67`이다(얼릴 때 화면 값). 64자 전체는 11c(`settings/pilot2_v1.json`)의 요청 지문 memory 칸과 같아야 하고, 11c 뒤에 여기 적는다.
    - 걸린 설정: 11c `settings/pilot2_v1.json`(설계안 10.3의 "얼린 뒤 연습 문항으로 한 번 더"). 본실험 설정에도 건다.
- 얼린 뒤에는 고치지 않는다. 다시 얼려야 하면 새 이름으로 얼린다.
