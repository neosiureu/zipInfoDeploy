# 문항 (`experiment/questions`, 순서 7)

만들기 설계안 9절(9.1 유형, 9.2 배정, 9.3 정답)과 순서 7 설계 c판의 문항 쪽이다. 문항은 `prep questions`(`experiment/prep/questions.py`)가 틀 문장 파일로 만든다.

| 파일 | 내용 | git |

| `questions_v0.json` | 문항 파일. `prep questions`가 쓰고 하네스가 읽는다(`harness/settings/pilot_v0.json`의 `files.questions`) | 관문 3까지 밖 |

- 문항별 정답은 `prep/out/answers_v0.json`에 쓴다(git 밖). 순서 8 채점기가 읽는다.

## 틀 문장 파일

```json
{"version": "v0", "templates": {"T1": ["…"], "T2": ["…"], "T3": ["…"], "T4": ["…"], "T5": ["…"]}}
```

- UTF-8(BOM 없음)이다.
- 글은 사용자가 쓴 그대로다. 앞뒤 빈칸만 떼고 NFC로 맞춘다.
    - 예외는 하나다. 사용자가 매물 이름 자리를 다른 꼴로 적었으면 `{이름}`으로 바꾸고, 바꾼 곳을 사용자에게 알린다.
- 차례는 사용자가 쓴 차례다. 틀 문장 고르기가 이 차례를 쓴다.

### 기계 검사

`prep questions`가 읽을 때 본다. 하나라도 걸리면 아무것도 쓰지 않고 멈춘다. 걸린 것은 모두 찍는다(유형, 몇 번째, 까닭). 고친 글은 사용자에게 다시 받는다.

1. **꼴**
    - 칸은 version과 templates뿐이다. version은 `v` 뒤에 숫자 1~3자다.
    - templates는 T1~T5 다섯뿐이고, 유형마다 4~6개다.
    - 틀 문장은 겹치지 않는다. 한 줄이고, 비지 않고, 앞뒤 빈칸이 없고, NFC다.
2. **자리:** `{이름}`은 많아야 한 번이다. 그 밖의 `{`·`}`는 없다. `{이름}` 밖에 "이름"이라는 글자가 없다.
3. **`{이름}` 바로 뒤:** 아래일 때만 지난다.
    - 끝, 빈칸, 문장부호(유니코드 P 갈래)
    - 받침과 상관없는 말로 시작할 때: 의·에·에서·에게·한테·도·만·보다·까지·부터·하고·처럼·마다·인
    - 단, "에요"·"에여"로 시작하면 걸린다.
4. **기간 말:** "최근 1개월"·"최근 3개월"·"최근 6개월"·"최근 1년"뿐이다.
    - 이 넷을 뺀 글에는 "최근", 숫자(파이썬 `isdigit`로 본다. 0~9와 전각 숫자·① 같은 것), 요즘·요새·근래·올해·작년·지난·개월·분기·최신이 없다.
    - T1·T2·T4에는 기간 말이 없다.
    - T3에는 기간 말이 꼭 한 번 있고, "최근 1개월"·"최근 3개월"·"최근 6개월" 가운데 하나다. T3 틀 문장들이 이 셋을 모두 쓴다.
    - T5에는 "최근 1년"만 꼭 한 번 있다.
5. **"단지":** T2·T5에는 있고, T1·T3·T4에는 없다. `{이름}` 밖에서 본다.

기계로 못 보는 것은 사람이 본다. 유형마다 지킬 것, T5의 "단지"가 건수에만 걸리는지, 도구·API·사이트 이름, 답을 암시하는 말, 다섯 밖의 기간 말 같은 것이다.
매물마다 다른 말(집 종류, 거래 종류, 층·크기·새 집인지)도 사람이 본다. 틀 문장은 그 유형의 모든 매물에 붙기 때문이다. T4는 월세 매물뿐이라 월세·보증금·환산은 된다.

틀 문장 파일이 있으면 하네스 시험 `TemplatesCheckTest`가 돈다(순서 7b).

- 파일 지문(줄 끝을 LF로 맞춘 SHA-256)이 맞춘 값과 같은지 본다. 틀 문장을 고치면 이 시험이 멈추고, 사람이 다시 본 뒤 값을 고친다.
- 틀 문장마다 ⓪의 절에서 유형의 카드를 한글 낱말로 찾는지 본다(T1·T2 K04, T3 K04·K05, T4 K04·K07, T5 K04·K05·K08).
- 틀 문장마다 ⓪의 분모와 절 수를 찍는다. 틀 문장 글은 시험에 넣지 않는다.

## 문항 만들기

1. **배정:** 9.2 그대로다(`prep/answers.py`의 `assign`). 매물 75개 × 3 = 225문항이다.
2. **틀 문장 고르기(고루 나누기)**
    - 나눔(연습·본시험)과 유형마다 문항을 `H(qtext, 단지ID|유형)`가 작은 순으로 세운다. 같으면 매물 키 순이다.
    - i번째(0부터) 문항에 그 유형의 i mod k번째 틀 문장을 준다. k는 그 유형의 틀 문장 수다.
    - 그래서 틀 문장마다 연습에서 한 번 이상 쓰인다. 남는 몫은 파일 차례로 앞의 틀 문장에 간다.
3. **채우기:** `{이름}`을 매물 블록의 stockName(`prep/out/listings_input_v1.json`)으로 바꾼다. 그 밖은 틀 문장 그대로다. 채운 글이 NFC가 아니거나 중괄호가 남으면 멈춘다.
4. **창:** T3는 고른 틀 문장의 기간 말이다(1·3·6달, 202610이 끝). 나머지는 12달이다.
5. **ID:** 매물 키 차례, 그 안에서 유형 차례로 `q001`~`q225`다. 틀 문장과 상관없다.

## 문항 파일

```json
{"version": "v0", "questions": [{"id": "q001", "key": "L01", "qtype": "T1", "split": "연습", "text": "…"}, …]}
```

- 두 나눔의 225개를 모두 담는다. 하네스는 설정의 split과 같은 문항만 고른다.
- UTF-8(BOM 없음), LF, 칸 차례 고정, 들여쓰기 1칸, 끝에 줄바꿈 하나다.

## 문항별 정답 (`prep/out/answers_v0.json`)

```json
{"version": "v0", "questions_sha256": "…", "answers": [{"id": "q001", "key": "L01", "split": "연습", "qtype": "T1", "months": 12, …}, …]}
```

- `questions_sha256`은 함께 쓴 문항 파일의 SHA-256이다(줄 끝을 LF로 맞춤, 대문자). 채점기가 대 본다.
- 문항마다 대조용 정답(`prep/out/answers_check_v1.json`, 순서 3a)의 같은 (매물, 유형, 창) 줄에 id·split을 더한다.
    - 칸 차례: id, key, split, qtype, months, scope, call, sample, listing_value, 값 칸(basis, 월세는 deposit·monthly·converted), diff, t5_count(T5만)
- 지금 셈한 대조용 정답이 그 파일과 다르면 멈춘다. 그래서 이 값들은 Java 도구와 대 본 값이다(하네스 검사 줄 "대조한 문항").

## 명령

`experiment` 폴더에서 돌린다.

```
python -X utf8 -B -m prep questions
```

- `prep build`와 `prep answers`를 먼저 돌려야 한다. 매물 파일, 매물 입력, 거래 파일의 해시를 대 보고, 대조용 정답 파일이 있어야 한다.
- 화면에는 수와 해시만 낸다. 매물 이름·주소·단지ID·질문 글은 찍지 않는다.
